# URKTV 交接（2026-11-27）

> 新對話先讀這份。讀完就知道現在停在哪、怎麼建置部署測試、老闆的規矩、還沒解的問題。

## 1. 這是什麼

線上 KTV 網站 **URKTV**，對標 app.kareokie.com。老闆定案的做法：

- **只播 YouTube 官方 MV**（官方嵌入播放器），**網站絕不存放、不轉播任何音樂**。
- **去人聲在用戶自己的電腦上即時做**：Chrome 擴充功能接走 MV 的聲音，用 AI 分出伴奏和人聲，只給用戶自己聽。
- **灰條（原唱音高）和歌詞時間**也由用戶電腦即時算（從分出來的人聲），之後可由老闆的 RTX 5070 Ti 先算好熱門歌、大家共用（還沒做批次）。
- 手機目前只能唱原唱 MV（瀏覽器不能裝擴充功能）。
- 網站不設密碼。網址老闆說「先不公開」（已在 repo 的 manifest 裡，僅此而已，不要另外宣傳）。

## 2. 現在的狀態

- 正式站：Cloudflare Workers（名稱 `urktv`），網站檔放 Workers KV，房間用 Durable Objects。`python3 deploy/deploy.py` 會印出網址。
- 分支：`main`，最後一個 commit 是這份交接。
- 擴充功能版本：**0.3.4**（`extension/manifest.json`）。尚未上架 Chrome 商店，用戶要開「開發人員模式」載入未封裝項目，**不能自動更新**（網站會提示版本過舊）。
- 測試：`npm test`（67 項）要全過。

### 老闆最後回報、還沒確認修好的問題（最優先）

1. **灰條沒出來／亂抓／不動**。0.3.3 加了「人聲要比漏進來的音樂大才算在唱」，0.3.4 放寬到 8%，並在灰條區顯示空白原因。**沒辦法在這個環境用真的 YouTube 驗證**（沙盒連不到 YouTube 播放），只用本機音檔驗過。請老闆截圖灰條區那行字＋「擴充功能 · 診斷」內容。

4. **唱歌畫面醜**。改過三輪（霓虹房、KTV 式灰條、彩色＋歌詞字），老闆仍不滿意，沒有給具體方向，下次請他給參考畫面或指定哪一塊。
5. **高品質模型在老闆電腦上的速度**：他的 Chrome 用到主機板內建 AMD 顯示卡（0.57 倍）。0.3.2 起會實測顯示卡和 CPU 取快的。等他回報「高品質模型跑在…」「速度 X 倍」。他有 5070 Ti 但螢幕線可能插在主機板上。

### 三種聲音模式（Stage）

- 🎤 原唱（人聲 100%）／🎙️ 導唱（用戶自訂的淡原唱）／🎶 伴唱（0%）：三者用**同一個輕量 AI**，切換只是調人聲大小。
- 品質「一般」= Spleeter；「✨ 高品質」= MDX Karaoke 2（要兩步確認）。
- 沒裝擴充功能：只能播原 MV，沒有灰條。

## 4. 建置、部署

```bash
npm ci
npm run models        # 下載模型到 public/models（不進 git）
npm test
npm run build         # 會先打包擴充功能 zip（scripts/pack-extension.mjs）
```

部署（Cloudflare 權杖已存在這個雲端環境的網路密鑰裡，代理會自動帶上；**不要請老闆在對話貼金鑰**，要用安全表單 `request_credential`）：

```bash
S=<scratchpad>; rm -rf $S/site && cp -r dist $S/site
rm -rf $S/site/catalog $S/site/exttest.html $S/site/exttest-embed.html   # 測試頁和含音檔的 catalog 不上線
python3 -I deploy/deploy.py <Cloudflare 帳戶ID> $S/site urktv
```

- 帳戶 ID 不寫在 repo：用同一個權杖打 Cloudflare API `GET /accounts` 取得。
- 只改 Worker：加 `--worker-only`。
- 每次改擴充功能：升 `extension/manifest.json` 的版本號（網站靠它提示用戶更新）。
- 上線後首頁一分鐘內更新；網站自己會偵測 `build.txt` 跳「有新版本」。

## 5. 測試方法（改畫面或引擎後要跑）

這個環境**連不到真的 YouTube 播放**，所以用假 YouTube：`?fakeyt` 會把播放器換成本機音檔（`public/bench/clip.mp3`，CC 授權）。

```bash
npx vite preview --port 4173 --strictPort &
npx vite preview --port 4174 --strictPort --host 127.0.0.1 &   # 假 YouTube 的來源
mkdir -p /tmp/urktv-e2e
node scripts/e2e/site-ktv.cjs      # 真擴充功能＋假 YouTube：開唱、切伴唱、男調、音效、變聲
node scripts/e2e/starttime.cjs     # 按開始到畫面播放要幾秒
node scripts/e2e/cache.cjs out.png # 唱過的歌是否存下分析
node scripts/e2e/site-hq.cjs       # 高品質模型路徑
node scripts/e2e/demo.cjs lane.png <假歌聲.wav> 9500   # 開嗓練習＋假麥克風，看灰條畫面
SITE_URL=<正式站> node scripts/e2e/room.cjs room.png   # 兩個瀏覽器進同一房間
SITE_URL=<正式站> node scripts/e2e/lyrtest.cjs         # 用真的 MV 標題測歌詞搜尋（要 ?debug）
node scripts/e2e/kstest.mjs        # 升降 Key 音高準確度
node scripts/e2e/wasmtime.mjs <模型> <執行緒> <形狀> <秒數>   # 模型在 WASM 的速度
```

注意：

- Node 的 `fetch`／WebSocket 不走這個環境的代理，連外網要用 `curl` 或 Python `urllib`，或在 Playwright 瀏覽器裡做。
- 無頭瀏覽器沒有 WebGPU，高品質模型只能測 CPU。
- 測試機只有 4 個虛擬核心，速度數字比一般電腦悲觀。

## 6. 實測過的數字（不要重測）

| 項目 | 結果 |
|---|---|
| Spleeter（WASM，1 執行緒） | 約 8 倍即時（模型本身）；串流時 2 執行緒約 1.3～4 倍 |
| MDX Karaoke 2（WASM） | 1 執行緒 0.33 倍；4 執行緒 0.98 倍；老闆的 AMD 內顯 WebGPU 0.57 倍 |
| Karaoke 2 int8 量化 | 與原版只差 12dB（聽得出來），per-channel 版 ORT-web 不支援 → **不採用** |
| 升降 Key | 誤差 0.5% 以內 |
| 歌詞涵蓋（華／台／粵排行 60 首） | LRCLIB 有時間軸 72%、純文字 8%、沒有 20%；加網易雲後測試的 8 首全中 |
| 開始延遲 | 按開始到播放約 5 秒（測試機） |
